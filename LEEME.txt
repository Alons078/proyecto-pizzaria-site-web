REY PIZZARIA — prototipo

Cómo correrlo en tu computadora:
1. Necesitas Python instalado. Instala las dependencias:
   pip install -r requirements.txt --break-system-packages
2. Abre una terminal DENTRO de esta carpeta (rey-pizzaria).
3. Define una contraseña de administrador (OBLIGATORIO para entrar a /admin):
   - Mac/Linux: export ADMIN_PASSWORD="la-clave-que-quieras"
   - Windows (cmd):  set ADMIN_PASSWORD=la-clave-que-quieras
   Si no la defines, el panel /admin queda bloqueado (nadie puede entrar).
   En Render se define en Environment con el nombre ADMIN_PASSWORD.
4. Ejecuta: python3 app.py
5. En el navegador abre:
   - http://127.0.0.1:5000/               -> vista del cliente (blog)
   - http://127.0.0.1:5000/admin          -> panel del administrador (pide contraseña)
   - http://127.0.0.1:5000/funcionarios   -> registro de ventas por turno (pide la senha del turno)

CARRINHO DO CLIENTE E PEDIDOS PELO WHATSAPP:
Agora, ao clicar numa pizza, salgado, bebida ou promoção, o cliente vai
para uma página própria daquele produto, onde escolhe a quantidade (e, no
caso das promoções, os sabores de cada posição) e adiciona ao carrinho.
O carrinho fica salvo no próprio navegador do cliente (não no servidor),
então continua igual se ele voltar ao cardápio para adicionar mais coisas.
Na página do carrinho (ícone 🛒 no topo do site), o cliente revisa os
itens, escolhe retirada ou entrega, forma de pagamento, e ao confirmar o
pedido se abre o WhatsApp com uma mensagem pronta, já com a lista de itens
e o total, para ele enviar direto para a pizzaria.

IMPORTANTE: para isso funcionar, é preciso cadastrar o número de WhatsApp
da pizzaria no painel do administrador, na seção "Loja", campo "WhatsApp
para receber os pedidos" (com código do país e DDD, só números, ex.:
5521999998888). Sem esse número cadastrado, o botão de confirmar pedido
avisa o cliente que ainda não é possível fechar o pedido por lá.

Esse pedido feito pelo WhatsApp é só uma mensagem para o cliente confirmar
com a pizzaria — ele não fica registrado automaticamente no sistema de
vendas do painel do admin. Quem registra a venda no sistema (para entrar
nas estatísticas) continua sendo o funcionário, pela página /funcionarios,
depois de combinar o pedido com o cliente.

BASE DE DATOS (SQLite):
Los datos (cardápio, promociones, turnos, ventas) ahora se guardan en un
archivo pizzaria.db, no en data.json. No necesitas instalar nada aparte,
Python ya lo trae incluido. La primera vez que corras el proyecto, se crea
pizzaria.db solo y copia automáticamente lo que había en data.json (después
data.json se renombra a data.json.migrado, como respaldo).

IMPORTANTE para Render: el plan gratis/básico de Render borra los archivos
que se crean en el servidor cada vez que se reinicia o se actualiza el
código (esto incluye tanto pizzaria.db como las fotos subidas en
static/uploads/). Para que las ventas, el cardápio y las fotos NO se
pierdan con cada reinicio, hay que agregar un "Persistent Disk" desde el
panel de Render (Settings -> Disks) y montarlo en la carpeta del proyecto.
Sin eso, cada reinicio del servidor vuelve a copiar los datos originales
de data.json y las fotos subidas después se pierden.

Antes de subirlo a Render (o cualquier hosting real), configura estas
variables de entorno desde el panel de Render ("Environment"):
- ADMIN_PASSWORD -> la contraseña real del panel /admin
- SECRET_KEY     -> cualquier texto largo y aleatorio (ej. generado con
                     `python3 -c "import secrets; print(secrets.token_hex(16))"`)
Sin SECRET_KEY, las sesiones (logins) se cierran solas cada vez que
Render reinicia el servidor. Render define la variable PORT solo,
no hace falta tocarla. El Procfile ya usa gunicorn en vez del
servidor de pruebas de Flask.

Estructura que debe quedar (no muevas archivos sueltos):
  rey-pizzaria/
  ├── app.py
  ├── data.json
  ├── requirements.txt
  ├── Procfile
  ├── templates/  (cliente.html, admin.html, admin_login.html, funcionarios.html)
  └── static/     (style.css, client.js, admin.js, funcionarios.js, images/logo.jpg)

===========================================================
IMPRESIÓN AUTOMÁTICA EN LA IMPRESORA TÉRMICA (nuevo)
===========================================================

Ahora, cada vez que un cliente confirma un pedido en /carrinho, además
de abrirse el WhatsApp, el pedido queda anotado en el servidor para
que se imprima solo en la impresora térmica de la pizzería (probado
con la Knup KP-IM607, pero funciona con cualquier impresora térmica
USB que Windows reconozca como impresora normal).

Cómo funciona: el pedido NO se imprime desde el servidor de Render
directamente (Render no puede "ver" una impresora que está en la
computadora de la pizzería). En cambio, un programita chiquito
(agente_impressora/imprimir_agent.py) corre en esa computadora,
pregunta cada 5 segundos si llegó un pedido nuevo, y si llegó, lo
manda a imprimir y avisa al servidor que ya se imprimió.

PASOS PARA DEJARLO FUNCIONANDO (una sola vez):

1. En la computadora de la pizzería (con Windows), conectá la
   impresora por USB e instalá su driver si Windows lo pide. Debe
   aparecer en Configuración > Bluetooth y dispositivos > Impresoras
   y escáneres.

2. Instalá Python en esa computadora si no lo tiene (python.org,
   marcando la casilla "Add python.exe to PATH" al instalar).

3. Copiá la carpeta "agente_impressora" a esa computadora (puede ir,
   por ejemplo, en el Escritorio).

4. Abrí una terminal (cmd) dentro de esa carpeta y ejecutá:
     pip install -r requirements.txt

5. Ejecutá:
     python listar_impressoras.py
   Copiá el nombre EXACTO que aparezca entre comillas.

6. Abrí imprimir_agent.py con el Bloc de notas y completá las tres
   líneas de arriba (CONFIGURAÇÃO):
     SERVER_URL   -> la dirección de tu sitio en Render
     PRINT_TOKEN  -> el token que aparece en /admin, sección Loja,
                     "Agente de impressão" (botón "Gerar novo" si
                     todavía no hay uno)
     PRINTER_NAME -> el nombre que copiaste en el paso 5

7. Ejecutá:
     python imprimir_agent.py
   Dejá esa ventana abierta mientras la pizzería esté recibiendo
   pedidos. Cada pedido nuevo se imprime solo, como un ticket de
   cocina (nombre del cliente, ítems, total, forma de pago y
   observaciones).

8. (Opcional, para que arranque solo con la computadora) Creá un
   acceso directo a imprimir_agent.py dentro de la carpeta de Inicio
   de Windows (Win+R, escribí shell:startup, Enter).

Notas importantes:
- Si alguna vez cambiás el token desde /admin (botón "Gerar novo"),
  tenés que actualizar también PRINT_TOKEN en imprimir_agent.py, o
  el programa va a dejar de poder conectarse.
- Este ticket es solo para que la cocina vea el pedido más rápido.
  Igual que antes, la venta real sigue registrándose a mano por el
  empleado en /funcionarios — la impresión no reemplaza eso.
- Si el pedido se abre en WhatsApp pero por algún motivo no se
  imprime (por ejemplo, la computadora de la pizzería estaba
  apagada), el mensaje de WhatsApp sigue llegando igual: la
  impresión es un extra, no el único aviso del pedido.


TAXA DE ENTREGA AUTOMÁTICA (por distância):
Ao escolher "Entrega (delivery)", o cliente digita o endereço e toca em
"Calcular taxa de entrega". O servidor geocodifica o endereço no Nominatim
(OpenStreetMap, grátis), calcula a distância em linha reta até a pizzaria
e aplica a regra: até FEE_RADIUS_KM = FEE_BASE; acima = FEE_EXTRA; acima de
MAX_DELIVERY_KM = fora da área (a pizzaria combina pelo WhatsApp).
Cada endereço só vai UMA vez ao Nominatim: depois fica na tabela
geocoded_addresses (cache). Se a geocodificação falhar, o pedido segue
normalmente com "taxa a combinar".

Variáveis de ambiente no Render:
- PIZZERIA_LAT, PIZZERIA_LON  (OBRIGATÓRIAS) coordenadas da pizzaria.
    Google Maps -> clique direito no ponto da loja -> copie os dois números.
- FEE_RADIUS_KM (3), FEE_BASE (5.00), FEE_EXTRA (8.00), MAX_DELIVERY_KM (10)
    -> combinar os valores em R$ com o dono.
- GEOCODE_CONTEXT ("Rio de Janeiro, RJ, Brasil") e NOMINATIM_USER_AGENT
    (ex.: "Rey-Pizzaria/1.0 (seu-email@dominio.com)").
O Procfile agora usa "--workers 1 --threads 4": a fila de 1 req/s vive na
memória de UM processo. Não aumente --workers sem mudar essa parte.

Testes: python -m unittest tests.test_geocoding -v
