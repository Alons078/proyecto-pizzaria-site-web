REY PIZZARIA — prototipo

Cómo correrlo en tu computadora:
1. Necesitas Python instalado. Instala las dependencias:
   pip install -r requirements.txt --break-system-packages
2. Abre una terminal DENTRO de esta carpeta (rey-pizzaria).
3. (Opcional pero recomendado) define una contraseña de administrador:
   - Mac/Linux: export ADMIN_PASSWORD="la-clave-que-quieras"
   - Windows (cmd):  set ADMIN_PASSWORD=la-clave-que-quieras
   Si no la defines, se usa la clave por defecto "admin123" — sirve
   para probar en tu compu, pero NO la dejes así en Render.
4. Ejecuta: python3 app.py
5. En el navegador abre:
   - http://127.0.0.1:5000/               -> vista del cliente (blog)
   - http://127.0.0.1:5000/admin          -> panel del administrador (pide contraseña)
   - http://127.0.0.1:5000/funcionarios   -> registro de ventas por turno (pide la senha del turno)

CARRINHO DO CLIENTE E PEDIDOS PELO WHATSAPP:
Agora, ao clicar numa pizza, salgado, bebida ou promoção, o cliente vai
para uma página própria daquele produto, onde escolhe a quantidade (e, no
caso das promoções, os sabores de cada posição) e adiciona ao carrinho.
O carrinho fica salvo no próprio navegador do cliente (não no servidor),
então continua igual se ele voltar ao cardápio para adicionar mais coisas.
Na página do carrinho (ícone 🛒 no topo do site), o cliente revisa os
itens, escolhe retirada ou entrega, forma de pagamento, e ao confirmar o
pedido se abre o WhatsApp com uma mensagem pronta, já com a lista de itens
e o total, para ele enviar direto para a pizzaria.

IMPORTANTE: para isso funcionar, é preciso cadastrar o número de WhatsApp
da pizzaria no painel do administrador, na seção "Loja", campo "WhatsApp
para receber os pedidos" (com código do país e DDD, só números, ex.:
5521999998888). Sem esse número cadastrado, o botão de confirmar pedido
avisa o cliente que ainda não é possível fechar o pedido por lá.

Esse pedido feito pelo WhatsApp é só uma mensagem para o cliente confirmar
com a pizzaria — ele não fica registrado automaticamente no sistema de
vendas do painel do admin. Quem registra a venda no sistema (para entrar
nas estatísticas) continua sendo o funcionário, pela página /funcionarios,
depois de combinar o pedido com o cliente.

BASE DE DATOS (SQLite):
Los datos (cardápio, promociones, turnos, ventas) ahora se guardan en un
archivo pizzaria.db, no en data.json. No necesitas instalar nada aparte,
Python ya lo trae incluido. La primera vez que corras el proyecto, se crea
pizzaria.db solo y copia automáticamente lo que había en data.json (después
data.json se renombra a data.json.migrado, como respaldo).

IMPORTANTE para Render: el plan gratis/básico de Render borra los archivos
que se crean en el servidor cada vez que se reinicia o se actualiza el
código (esto incluye tanto pizzaria.db como las fotos subidas en
static/uploads/). Para que las ventas, el cardápio y las fotos NO se
pierdan con cada reinicio, hay que agregar un "Persistent Disk" desde el
panel de Render (Settings -> Disks) y montarlo en la carpeta del proyecto.
Sin eso, cada reinicio del servidor vuelve a copiar los datos originales
de data.json y las fotos subidas después se pierden.

Antes de subirlo a Render (o cualquier hosting real), configura estas
variables de entorno desde el panel de Render ("Environment"):
- ADMIN_PASSWORD -> la contraseña real del panel /admin
- SECRET_KEY     -> cualquier texto largo y aleatorio (ej. generado con
                     `python3 -c "import secrets; print(secrets.token_hex(16))"`)
Sin SECRET_KEY, las sesiones (logins) se cierran solas cada vez que
Render reinicia el servidor. Render define la variable PORT solo,
no hace falta tocarla. El Procfile ya usa gunicorn en vez del
servidor de pruebas de Flask.

Estructura que debe quedar (no muevas archivos sueltos):
  rey-pizzaria/
  ├── app.py
  ├── data.json
  ├── requirements.txt
  ├── Procfile
  ├── templates/  (cliente.html, admin.html, admin_login.html, funcionarios.html)
  └── static/     (style.css, client.js, admin.js, funcionarios.js, images/logo.jpg)

Qué cambió en esta versión:
- Fondo blanco en toda la página (antes era oscuro).
- Nombre del negocio: "Rey Pizzaria".
- Tu logo ya está incluido y aparece chico junto al nombre en el
  header, y grande arriba del post del día. Para cambiarlo, usa el
  campo "Logo da pizzaria" dentro de /admin.

  contraseña (la configuras en /admin, sección "Turnos de
  funcionários"). El empleado entra con la contraseña de su turno

  el detalle de esas ventas en /admin, sección "Vendas dos
  funcionários" (total general, total de los últimos 7 días y
  desglose por turno).
- Se corrigieron dos errores del prototipo anterior: un enlace roto
  del logo en la vista del cliente, y un producto de prueba vacío
  que había quedado en el cardápio.
